# dsh-linguist-tools

[English](README.md) · **Русский**

Host-плагин DSH для каталогов переводов Qt Linguist (файлы `.ts`). Даёт агенту
восемь инструментов и один навык, редактирует каталоги через побайтно точную
запись в формате `lupdate` и не требует Python, бинарника `lupdate` или
зависимостей во время выполнения.

Движок самодостаточен: устойчивый к ошибкам разбор XML, стабильные
идентификаторы сообщений, модель пяти состояний, правила проверки,
необязательный глоссарий терминов и память переводов. Он работает с любой
структурой проекта и любой языковой парой: ничего о конкретном продукте, языке
или каталоге не зашито в код.

## Инструменты

| инструмент | назначение |
|------------|------------|
| `qt_ts_status` | количество сообщений по состояниям, расхождения между языками, отклонения форматирования, блокировки записи |
| `qt_ts_find` | фильтрация сообщений одного языка по состоянию, контексту, тексту, расположению или id |
| `qt_ts_show` | одно сообщение во всех языках, места в исходниках, необязательные фрагменты кода |
| `qt_ts_lint` | плейсхолдеры, формы множественного числа, пустые переводы, мнемоники, разметка, алфавиты, дубликаты, рассинхронизация, глоссарий |
| `qt_ts_apply` | проверенная запись пакета переводов, состояний и примечаний по принципу «всё или ничего» |
| `qt_ts_prune` | удаление исчезнувших и устаревших сообщений (по умолчанию пробный запуск) |
| `qt_ts_memory` | существующие переводы похожих исходных строк |
| `qt_ts_glossary` | список терминов или поиск по ним |

Каждый инструмент принимает `dir`; по умолчанию это `translations` относительно
каталога сеанса. Языки задаются как `ru`, `ru_RU`, `zh`, список через запятую,
`all` или путь к `.ts`. Идентификатор сообщения — первые восемь шестнадцатеричных
символов `sha1(context \0 source \0 comment)`, одинаковый во всех языковых файлах.

## Навык

Плагин также регистрирует навык `qt-linguist`. Он описывает порядок работы
(status → lint → find → show → apply → lint), пять состояний сообщений, границу
ответственности `lupdate`, требования к качеству перевода и необязательный
глоссарий. Модель загружает его по запросу, поэтому в обычном запросе он не
занимает место.

## Безопасность

- Чтение и запись идут через `ctx.fs`, поэтому действуют песочница сеанса и
  политика наблюдения «сначала чтение, потом запись».
- Документ записывается, только если все конструкции XML можно воспроизвести.
  Отклонения только в форматировании выводятся как format drift и нормализуются
  при следующей записи — так же, как это сделал бы `lupdate`.
- `qt_ts_apply` сначала проверяет весь пакет: если хотя бы одна запись отклонена,
  файл не меняется. `dry_run` показывает результат без записи. `force` обходит
  ошибки уровня ошибок.
- `qt_ts_prune` по умолчанию работает с `dry_run: true`.
- Плагин никогда не запускает `lupdate` или `lrelease`; он меняет только
  существующие сообщения, их состояние и комментарии переводчика.

## Глоссарий

`glossary.json` рядом с `.ts` необязателен. Формат:

```json
{
  "version": 1,
  "terms": [
    {
      "term": "probe",
      "note": "measuring probe",
      "ru": { "translation": "щуп", "match": "щуп\\w*", "variants": ["зонд"] },
      "zh": { "translation": "测头", "avoid": ["探头"] },
      "exceptions": ["2b8fe176"]
    }
  ]
}
```

- `status`: `approved` (по умолчанию) или `proposed`.
- `match`: регулярное выражение, допускающее словоформы; по умолчанию для
  перевода берётся экранированный текст, для термина — поиск целых слов.
- `variants`, `avoid`, `note`, `contexts` (регулярное выражение по именам
  контекстов) и `exceptions` (идентификаторы сообщений) необязательны.
- Термины ищутся от самого длинного совпадения, поэтому `probe head` скрывает
  `probe`.

`qt_ts_lint` сообщает о `glossary-avoid` (предупреждение), `glossary` /
`glossary-proposed` (информация) и `glossary-invalid` (ошибка). `qt_ts_apply`
отклоняет пакет, если глоссарий некорректен.

## Структура репозитория

| путь | содержимое |
|------|------------|
| `index.js` | `apply` плагина, внедрение сервисов, регистрация навыка |
| `lib/` | разбор XML, сериализатор, модель, запросы, проверки, глоссарий, редактирование, память переводов |
| `tools/` | регистрация восьми инструментов `qt_ts_*` |
| `test/` | тесты и синтетические фикстуры (`test/fixtures/example/`, `test/fixtures/edge/`) |
| `scripts/generate-fixtures.mjs` | пересоздаёт фикстуры |
| `locale/`, `icon.svg`, `cordis.patch.yml` | метаданные отображения и строка Host |

Корень репозитория — устанавливаемый бандл; движок находится в `lib/`.

## Настройка

Конфигурация строки необязательна; у каждого ключа есть значение по умолчанию:

```yaml
- id: dsh-linguist-tools
  name: dsh-linguist-tools
  config:
    translationsDir: translations
    glossaryFile: glossary.json
    buildDirectories: [build, out, dist]
    maxFileBytes: 16777216
    defaultLimit: 50
    maxLimit: 500
    codeContextRadius: 3
    allowWrites: true
```

## Установка

Пакет — обычная зависимость pnpm, поэтому подходят и ссылка на GitHub, и
локальная копия. В Desktop используйте Plugin Manager; из оболочки:

```sh
# из GitHub (добавьте #<branch-or-commit>, чтобы зафиксировать ревизию)
dsh plugin --profile <profile> add github:extreme-russian-dsh-fandom/dsh-linguist-tools

# из локальной копии
dsh plugin --profile <profile> add C:\path\to\dsh-linguist-tools
```

`github:` — сокращение pnpm для GitHub, а не схема DSH: `dsh plugin` передаёт
аргументы в pnpm, а Plugin Manager при установке сначала проверяет репозиторий
через `git ls-remote` и только потом запускает `pnpm add`. Git-зависимость
версионируется указанным ref'ом (или веткой по умолчанию), поэтому фиксируйте
тег, коммит или ветку, если в ветке по умолчанию плагина ещё нет.

Репозиторий: <https://github.com/extreme-russian-dsh-fandom/dsh-linguist-tools>.

Замените `<profile>` на имя своего профиля (`desktop`, `web`, `tui`, ...).
Установка локального каталога создаёт ссылку, поэтому после правок достаточно
повторно включить плагин. Установка спецификации GitHub копирует пакет: сначала
push, затем переустановка, чтобы подхватить изменения.

Патч бандла вставляет одну строку, `dsh-linguist-tools`. Зависимостей и шага
сборки нет.

## Разработка

```
node --test --experimental-test-isolation=none "test/*.test.mjs"
```

Тесты покрывают побайтовые круговые преобразования, крайние случаи CRLF и
сущностей, заблокированные и конфликтующие каталоги, глоссарий, правила проверки,
отклонение записей, запись «всё или ничего» и предпросмотр prune. Фикстуры в
`test/fixtures/example/` синтетические, покрывают все состояния сообщений и
указывают расположения на `test/fixtures/src/`, поэтому фрагменты кода работают.
Пересоздать их можно командой `node scripts/generate-fixtures.mjs`; фикстуры
`edge/` покрывают неподдерживаемые конструкции, конфликты слияния и отклонения
форматирования.

## Ограничения

- Запись воспроизводит конструкции, которые создаёт `lupdate`. Неизвестные
  элементы и атрибуты, `<lengthvariant>` и несовпадение при обратном разборе
  делают файл доступным только для чтения (`write-blocked`), чтобы не потерять
  данные.
- `lupdate` остаётся единственным способом добавить сообщения и обновить
  расположения.
- Похожесть текстов считается коэффициентом Дайса по биграммам символов; оценки
  относительны внутри этого плагина и несравнимы с другими инструментами памяти
  переводов.
